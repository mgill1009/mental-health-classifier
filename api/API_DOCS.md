# API — Local Setup & Testing

## Requirements

- Python 3.11+
- scikit-learn **1.8.0** (must match the version used to save `pipeline.pkl` in notebook 02)
- Both model artefacts at the correct paths:
  - `models/baseline/pipeline.pkl` — generated by notebook 02
  - `models/distilbert/distilbert-mental-health/` — generated by notebook 03

---

## Starting the API

```bash
cd api
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8080 --reload
```

On startup you should see:

```
INFO  main  Startup — MODEL_TYPE=both
INFO  main  TF-IDF ready in 167ms
INFO  main  DistilBERT ready in 1043ms
INFO  Application startup complete.
```

The `MODEL_TYPE` environment variable controls which model(s) load at startup:

| `MODEL_TYPE` | Models loaded | Used by |
|---|---|---|
| `both` (default) | TF-IDF + DistilBERT | Cloud Run combined service, local dev |
| `tfidf` | TF-IDF only | GKE TF-IDF pods, dedicated Cloud Run service |
| `distilbert` | DistilBERT only | GKE DistilBERT pods, dedicated Cloud Run service |

---

## Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Liveness + readiness probe — returns MODEL_TYPE and serving list |
| GET | `/labels` | Returns the label mapping (0/1/2 → risk tier) |
| POST | `/predict?model=tfidf` | Inference using TF-IDF + Logistic Regression |
| POST | `/predict?model=distilbert` | Inference using fine-tuned DistilBERT |
| POST | `/tfidf/predict` | TF-IDF inference (GKE Ingress path) |
| POST | `/distilbert/predict` | DistilBERT inference (GKE Ingress path) |

Interactive docs available at: **http://localhost:8080/docs**

### TF-IDF — clear High Risk case

```bash
curl -X POST "http://localhost:8080/predict?model=tfidf" \
  -H "Content-Type: application/json" \
  -d '{"text": "I have not been able to get out of bed for weeks"}'
```

```json

  "risk_tier": 2,
  "risk_label": "High Risk",
  "confidence": 0.6255,
  "probabilities": {
    "Low Risk": 0.2001,
    "Moderate Risk": 0.1744,
    "High Risk": 0.6255
  },
  "model": "tfidf",
  "latency_ms": 4.0
}
```

### DistilBERT — same text, higher confidence

```bash
curl -X POST "http://localhost:8080/predict?model=distilbert" \
  -H "Content-Type: application/json" \
  -d '{"text": "I have not been able to get out of bed for weeks"}'
```

```json
{
  "risk_tier": 2,
  "risk_label": "High Risk",
  "confidence": 0.9353,
  "probabilities": {
    "Low Risk": 0.0629,
    "Moderate Risk": 0.0018,
    "High Risk": 0.9353
  },
  "model": "distilbert",
  "latency_ms": 252.6
}
```

Both models agree on **High Risk**. DistilBERT is more confident (93.5% vs 62.6%) because it understands the sentence contextually. TF-IDF relies on keyword presence — this sentence lacks explicit keywords like "depression" or "suicidal" which limits its certainty.

> **Note on latency:** DistilBERT runs on CPU locally. First call is ~250–400ms; subsequent calls in the same session are faster once the CPU kernel is warm. On a T4 GPU (as used during training on Colab), p99 was ~15ms.

### TF-IDF vs DistilBERT — implicit distress (anhedonia)

This is a documented false negative case from the evaluation. Both models misclassify it because the text contains no distress keywords and is grammatically positive.

```bash
curl -X POST "http://localhost:8080/predict?model=tfidf" \
  -H "Content-Type: application/json" \
  -d '{"text": "my dog is the only thing that gives me genuine joy lately"}'
```

```json
{
  "risk_tier": 0,
  "risk_label": "Low Risk",
  "confidence": 0.6985,
  "probabilities": {
    "Low Risk": 0.6985,
    "Moderate Risk": 0.0861,
    "High Risk": 0.2155
  },
  "model": "tfidf",
  "latency_ms": 4.3
}
```

```bash
curl -X POST "http://localhost:8080/predict?model=distilbert" \
  -H "Content-Type: application/json" \
  -d '{"text": "my dog is the only thing that gives me genuine joy lately"}'
```

```json
{
  "risk_tier": 0,
  "risk_label": "Low Risk",
  "confidence": 0.9547,
  "probabilities": {
    "Low Risk": 0.9547,
    "Moderate Risk": 0.001,
    "High Risk": 0.0443
  },
  "model": "distilbert",
  "latency_ms": 67.9
}
```

Both predict **Low Risk** (incorrect — this expresses anhedonia). DistilBERT is *more* confident in the wrong answer (95.5% vs 69.9%), illustrating the model's limitation on implicit, positively-framed distress. This is one of the 14 remaining High Risk → Low Risk false negatives documented in notebook 03.

### Testing against deployed endpoints

**Cloud Run:**

```bash
export CLOUDRUN_URL="https://<your-cloudrun-url>"

curl -X POST "${CLOUDRUN_URL}/predict?model=tfidf" \
  -H "Content-Type: application/json" \
  -d '{"text": "I feel completely hopeless"}'
```

**GKE:**

```bash
export GKE_URL="http://<your-gke-ingress-ip>"

curl -X POST "${GKE_URL}/tfidf/predict" \
  -H "Content-Type: application/json" \
  -d '{"text": "I feel completely hopeless"}'

curl -X POST "${GKE_URL}/distilbert/predict" \
  -H "Content-Type: application/json" \
  -d '{"text": "I feel completely hopeless"}'
```

Note the different path structure: Cloud Run uses `?model=` query parameter; GKE uses path prefixes `/tfidf/` and `/distilbert/` routed by the Ingress.
